# PERCo Meal Control — учёт питания в столовой

Программа читает проходы из PERCo-Web и показывает их на дашборде (4 экрана). По желанию она блокирует
повторный проход в одном окне питания. Это один файл `perco-meal.exe`, ему не нужны ни интернет, ни
дополнительные программы.

---

## 1. Что нужно
- ПК или сервер с **Windows 10/11** в той же сети, что и PERCo-Web (`192.168.1.106`).
- В PERCo-Web включён модуль **WM04 «Интеграция с внешними системами»** (сейчас ознакомительный, ключ нужно ввести до ~07.12.2026).
- Оператор PERCo для программы. Рекомендуется отдельный **`meal-service`**:
  PERCo-Web → Администрирование → Операторы → Добавить. Нужны права: сотрудники (просмотр и редактирование),
  журнал событий, конфигурация (просмотр).

## 2. Установка
1. Создайте папку, например `C:\PercoMeal`.
2. Скопируйте в неё:
   - `perco-meal.exe`;
   - `config.example.yaml`, переименовав его в **`config.yaml`**.
3. Откройте `config.yaml` в Блокноте и заполните:
   ```yaml
   perco:
     url: http://192.168.1.106
     login: meal-service
     password: "пароль оператора"
   ```
   Остальные настройки уже подобраны под вашу систему: замок №1, шаблоны Завтрак/Обед/Ужин и т. д.

## 3. Первый запуск (проверка)
Откройте PowerShell в папке программы и выполните:
```powershell
cd C:\PercoMeal
.\perco-meal.exe
```
В окне должно появиться:
```
запуск: PERCo http://192.168.1.106, дашборд http://localhost:8080
окно Завтрак: 07:05–08:15 (шаблон 3)
...
сотрудники обновлены: 847 активных
```
Откройте в браузере **http://localhost:8080**. Если всё работает, остановите программу (`Ctrl+C`) и переходите к шагу 4.

> Ошибка «auth: …» значит неверный логин или пароль в `config.yaml`, а «connection refused» — нет связи с `192.168.1.106`.

## 4. Установка службой Windows (автозапуск)
PowerShell **от имени администратора**:
```powershell
cd C:\PercoMeal
.\perco-meal.exe install
.\perco-meal.exe start
```
Служба называется **«PERCo Meal Control»**. Она запускается вместе с Windows и перезапускается сама, если упадёт.

| Действие | Команда (PowerShell от администратора) |
|---|---|
| Остановить | `.\perco-meal.exe stop` |
| Запустить | `.\perco-meal.exe start` |
| Перезапустить | `.\perco-meal.exe restart` |
| Удалить службу | `.\perco-meal.exe stop` → `.\perco-meal.exe uninstall` |

## 5. Экраны
С любого ПК в сети: `http://<IP этого ПК>:8080`

| Экран | Адрес | Для кого |
|---|---|---|
| Рабочее место | `http://…:8080/#a` | администратор: последний проход, таблица дня, блокировки |
| Табло у входа | `http://…:8080/?kiosk=1#b` | большой экран у считывателя: зелёный или красный |
| Лента событий | `http://…:8080/#c` | журнал проходов, итоги дня, повторы |
| По приёмам пищи | `http://…:8080/#d` | три колонки, «ещё не были» |

**Отчёт за месяц:** кнопка «Отчёт за месяц» скачивает CSV для Excel.

> Если с другого ПК дашборд не открывается, разрешите порт 8080 в брандмауэре Windows (PowerShell от администратора):
> ```powershell
> New-NetFirewallRule -DisplayName "PERCo Meal 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
> ```

## 6. Блокировка повторного прохода
После первого прохода в окне программа блокирует сотрудника в PERCo до конца окна, и на повторное прикладывание
карты считыватель пищит. После окна блокировка снимается сама.

### Включение
1. В `config.yaml` задайте PIN и тестовых сотрудников:
   ```yaml
   blocking:
     admin_pin: "ваш PIN"
     test_user_ids: [960]
   ```
2. Перезапустите службу: `.\perco-meal.exe restart`.
3. На дашборде нажмите индикатор **«Блокировка: ВЫКЛ»**, введите PIN и выберите режим.

| Режим | Что происходит |
|---|---|
| **ВЫКЛ** (по умолчанию) | Старый метод: только дашборд, PERCo не меняется. При переключении сюда все блокировки программы **сразу снимаются**. |
| **ТЕСТ** | Блокируются только сотрудники из `test_user_ids`. |
| **ВКЛ** | Блокируются все. |

Рекомендуемый порядок: 2–3 дня в режиме **ТЕСТ**, затем **ВКЛ**.

### Управление
- Панель **«Активные блокировки»** (экран «Рабочее место»): кто заблокирован и до какого времени. Кнопки «Разблокировать» у каждого и «Снять все» требуют PIN.
- Если администратор заблокировал или разблокировал сотрудника в PERCo вручную, программа его решение **не отменяет**.

### Аварийное отключение
Если что-то пошло не так, сделайте **любое** из этого:
1. Дашборд → «Блокировка» → **ВЫКЛ**.
2. Команда в папке программы (работает и при запущенной службе):
   ```powershell
   .\perco-meal.exe unblock-all
   ```
3. Блокировка выключается полностью, если в `config.yaml` поставить `force_off: true` в секции `blocking` и
   перезапустить службу.
4. Если программа вообще не работает: PERCo-Web → Сотрудники → фильтр «Заблокированные» → разблокировать.

## 7. Обновление программы
```powershell
cd C:\PercoMeal
.\perco-meal.exe stop
# замените perco-meal.exe новым файлом
.\perco-meal.exe start
```
`config.yaml` и база `perco-meal.db` сохраняются.

## 8. Файлы в папке
| Файл | Что это |
|---|---|
| `perco-meal.exe` | программа |
| `config.yaml` | настройки (содержит пароль, не передавайте) |
| `perco-meal.db` | база проходов и блокировок (создаётся сама) |
| `perco-meal.log`, `perco-meal.log.1` | журнал работы, не больше 10 МБ каждый |

## 9. Если что-то не так
| Признак | Что проверить |
|---|---|
| Красная плашка «Нет связи с PERCo-Web» | доступен ли `http://192.168.1.106`, логин и пароль, лицензия WM04 |
| «Нет связи со службой учёта питания» | запущена ли служба (`.\perco-meal.exe start`), журнал `perco-meal.log` |
| Окна питания неверные | время в PERCo → Временные критерии (Завтрак/обед/Ужин); программа перечитывает их каждые 10 минут |
| «Не удаётся снять блокировку» | связь с PERCo; программа повторяет сама, при необходимости разблокируйте в PERCo |
| «Служба работает под оператором admin» | заведите оператора `meal-service` и укажите его в `config.yaml` |
